## 增量执行与失败处理

`.codex/progress.md` 在修改代码前建立并纳入Git。根AGENTS和NEXT_SESSION_PROMPT要求恢复时先读入口、进度、git diff及未跟踪文件；`task.py checkpoint` 记录阶段、代码指纹、HEAD、已完成/待完成/决定/下一步。任务写入时自动原子更新自己的进度区块，保留手写计划和其他任务。

`task.py run --timeout` 先持久化未知状态并显示日志路径，限时终止子进程组后记录124；键盘中断记录130。强制杀进程后的未知结果拒绝归档，阶段未完成也拒绝归档。此机制用于恢复工作，不保证外部连接永不中断。

浏览器画廊每完成一图原子保存一次回执，启动即清除旧成功状态；全部完成后才标记passed。上次告示牌测试误把已消费的toast事件当无响应，现断言实际提示文案或准确对白ID。失败日志保留；新增旧档fixture在序列化后注入旧坐标，首领受击fixture使用足以穿过原减伤的伤害，不改游戏减伤规则。
