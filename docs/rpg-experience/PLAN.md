# RPG体验升级执行计划

用户需求：USER_REQUEST.txt；基线cad2add。当前需求授权实际战斗/成长、地图、任务顺序、设施与剧情触发改造，并按章推进全游戏。原0.9及旧精英短战预算是比较基线，不是本轮禁止重平衡的条件；不恢复已撤回大重构，不改未定世界真相。

## 独立阶段

1. A audit：读取最终装配与真实路线，建立八章内容/拓扑/服务/节奏基线；运行三职业裸装、正常、优化培养及多图连续遭遇，保存正式截图。脚本时间只称脚本时间。
2. B design：全章节方向与可验证目标；第一章逐地图/任务/敌人/设施/触发变更表，先确认准备与刺杀后逃离的时间线。
3. C1 implementation：以独立任务实施第一章战斗成长、地下空间与探索、任务结果、设施和触发，每个子系统保存检查点。
4. D1 verification：三职业正常输入、主线与可选内容、成长对照、经济、旧档、一次性触发、桌面触控与三维地图验收，生成可试玩构建。主观乐趣/完整真人节奏另列待验。
5. E chapter rollout：第一章技术标准达到后，按第二至八章各自独立任务记录基线、实际改造、回归和缺口；不把规划写成实现，不以第一章替代全游戏。
6. Harness：复用六项Skill与context/index/check/task，加入成长对照、探索/内容/设施/触发证据及按需检索，保留 Narrative Harness。
7. Delivery：更新状态、验收、旧包保留与新包入口、任务证据；分阶段提交并推送main，核验远端。Git保存不等于发布网站。

## 验收原则

- 真实RPG与Lab共用运行规则；对比同一地图、等级、策略与种子下的培养收益，不只测单Boss。
- 地图必须分别证明可玩性、场景可信度、角色一致性；保存修改前后真实渲染与可达证据。
- 任务新增的是决策、路径、机制或世界反馈；不以数量和强制往返替代内容。
- 叙事按实际事件状态、知识隔离与七维编辑审查；准备探索集中在刺杀前，撤离保持紧张连贯。
- 旧档进度、已领奖、物品和角色成长保留；新机制迁移幂等，不访问个人存档。
- 全部失败和人工待验如实记录；历史0.6人工观察不被本轮脚本冒充关闭。

附件只提供文字，所提两张洞窟截图本轮未收到；先以现有原画、正式渲染和明确空间需求设计，不声称已做对应截图对照。
