# RPG 内容设计与技术验收

本规范用于明确的体验设计、章节改造和成长/探索/任务/设施/节奏优化。普通碰撞修复、文案错字或数值故障仍按所属领域检索，不要求读取八章资料。当前全游戏授权与实施顺序见根AGENTS；原0.6/0.9是保存的比较基线。按章独立任务，先试点、验证，再推广；不能用首章完成代表全游戏完成。

## 开工与事实来源

`context.py --task "具体章节和设计目标"` 按五种能力路由到真实实现、测试和本规范；章节/人物任务继续使用Narrative Harness。先看当前章稿、实际安装顺序、地图/任务/敌人注册表及真实存档，区分策划与运行。工具 `tools/balance_lab/experience-audit.mjs inventory <输出目录>` 导出最终地图、支路、NPC、物件与Saga动态任务；40px网格只诊断，不替代碰撞/可达验收。完整审计及各章预算在 `docs/rpg-experience/AUDIT.md`。

先写清问题、玩家当前行为、拟改变的决策及可验证结果。保留同一来源的改前快照、实际画面和经济事件。地图数、怪物数、任务数、文件数都不能作为质量结论。

## 战斗与成长

使用生产RPG的伤害、AI、属性、冷却、资源、掉落和存档；不得用预览无敌模式验证平衡。三职业至少比较合法初始武器/零加点、实际路线普通行装、仅使用已拥有装备与已获得点数的优化行装。完全卸掉武器可能禁止攻击，须单列，不能据此声称低培养有挑战。记录同一来源快照、同一遭遇、策略和种子；比较通关/失败、耗时、承伤、用药、法力空窗、技能使用和机制回合。优化方案可能牺牲生存，不能只报告有利指标。

普通怪群、连续多图和精英/Boss分别检查。连续遭遇不得偷偷补满资源；显式记录升级恢复、休息和重复入图收益。固定地区岗位与可读招式优先于按玩家等级追涨；用侧移、目标顺序、打断、反击窗口体现培养价值，不能只加血量或削弱玩家。现有群战工具：`experience-audit.mjs combat <输出目录> <真实路线目录>`；精英培养对照：`ASHEN_C1_ECONOMY=<路线目录> node tools/balance_lab/experience-elites.mjs <输出目录>`。12种种子的单体实验与群战脚本只是诊断，不是人类胜率。

## 地下城与探索

先给房间、道路与楼层明确用途，再放墙、物件和敌人。列出主路、分支、回路、入口/出口、战斗宽度及返回距离；支路要有真实资源、情报、服务或可选挑战。比较改前/改后实际路线，不用新增楼层、重复宝箱、随机装饰替代探索。任务无关的常驻刷新遵守GAME_SETTINGS，已经取得的任务证据不随刷新丢失。

执行MAP_QUALITY的三个独立维度。实际moveActor/clearLine验证每个入口到出口和新目标；实际战斗检查近战、远程、绕障和预警躲避；正式渲染截图与原画核对布局、脚锚、遮挡和角色轮廓。未提供的参考图不得声称对照过。角色或场景审美需要人类观察时保留待验，不把自动几何通过当作美学认可。

## 任务与内容

逐任务记录：接取理由、玩家实际行动、过程中的变化、结算、世界结果、首次及重复的返回成本。重要事件需要可理解的过程，短任务也可以保持短。检查同一事实是否被多次要求重做、同一NPC是否立即接交两次、奖励是否只给旗标而没有实际用途。完成后应能指出已修复通路、可用设施、NPC新行动或具体物品去向。优先整合同路目标和已有证据，避免全章都变成相同击杀/采集计数。

新旧条件有迁移：已完成不重做、已达标旧证据不作废、奖励幂等、部分进度保留。不能把旧击杀记录伪装成玩家已经调查过的新现场；必要时保留旧任务专用交付。随机物品任务不得靠低概率拖时长。

## 世界设施与经济

每项服务有真实地点/NPC、安全条件和事务：药品实际到账，休息实际恢复，装备预览和装备后的stats一致，出售和制作真实扣料/扣钱且不复制。验证距离、战斗/过场限制、背包满、钱不足、重复提交、读档和买卖套利。价格与奖励要结合纯主线、典型探索、完整探索、重复路线的真实现金流；不要为展示消费强行清空玩家资源。

检查“战利品→据点→出售/制作→换装→新挑战”是否能发生。复用已有第五章工坊与城镇服务，不另造功能相同的系统。使用 `ASHEN_C1_ECONOMY` 和 `ASHEN_C1_BALANCE` 将新结果写入本次目录，保留历史验收原件。

## 节奏与叙事整合

每章标明进入的人物状态、局部冲突、准备窗口、探索价值、高潮、离开原因和下一章交接。目标分钟是设计预算；脚本跳对白时间不能成为真人体验时长。紧迫逃亡不插入长采购教学或无关刷取；可选内容有返回窗口而不强迫全部完成。

场景触发须列出地点、进度、在场者/视角、已看标记、控制权、结算、读档和跳过恢复。不要在正在战斗、已有对白、切图或敌方弹丸未消失时覆盖pending。必要事件因不安全而推迟后应有安全时点兜底；旧存档已看不重播。玩家观看的私谈与角色亲见事实分开，所有对白继续按Narrative Harness做写前上下文与七维编辑审查。

## 自动门禁与交付

明确设计任务的 `task.py start` 会按目标登记 `experience_requirement`；普通故障修复不自动登记。完整章任务要求五项能力、三职业正常UI到章末、旧档和独立人类状态；单项设计只登记相关范围。任务记录中的当前需求决定是否采用整章门禁，不能用单项报告替代整章任务。

1. `python3 tools/harness/experience.py --template --chapter R01 --report docs/rpg-experience/c1/ACCEPTANCE.json` 生成未验收模板。单项使用重复的 `--scope combat` 等，范围为combat/exploration/quests/services/pacing。
2. 填写逐项判断和真实证据path/sha256；`comparison`记录三职业、starter/normal/optimized、same_source_snapshot、production_rules、human_win_rate_claim=false。整章的normal_input分别写input_method=normal_ui、state_mutation_hooks=false、ending_phase与证据；第八章还要求ending_flags.ch8Complete=true。隔离场景测试不能写成全程正常输入。
3. `python3 tools/harness/experience.py --report <报告>` 拒绝缺项、失败、过期、篡改、培养对照错误及未结束路线。task.py的`experience --id <任务> --report <报告>`持久挂接，finish再次检查；全游戏任务需八章报告。
4. 人类乐趣/节奏若未测，human.status=pending并提供playable_build、observation_template两份哈希引用与remaining。工具只报告technical_pass和human_status，绝不将pending改成pass。真人通过必须记录观察者、时间和原始观察证据。旧0.6人工任务保持独立，不能被本门禁代替。

脚本只能核验声明与证据完整性，不能自动判文学、美学或乐趣。五项编辑判断须引用具体场景和实测结论；`unchanged`表示实际审阅确认本章既有内容已满足本项，仍须理由与证据。地图三维和Narrative门禁继续独立执行。

体验门禁使用运行章ID R01–R08，与叙事文学卷章分开；旧报告V01C01–V01C08只按历史别名兼容，不据此授予文学正史。
