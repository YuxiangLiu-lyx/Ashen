# 章节剧情记录与开发流程

适用：剧情开发、章节重构、影响叙事的地图与演出任务。纯数值、工具或普通美术修复不因此加载完整世界观。当前运行事实仍由 `dist/` 与实测描述；用户的新方向是变更依据，策划稿不等于已实现内容。

2026-10-14扩展到所有人物对白、支线/NPC事件、日常、争执、情感或政治交流、认知/关系变化、伏笔与游戏事件交接。运行入口仍是 context.py、index.py、check.py、task.py 和既有剧情 Skill；[叙事 Harness](NARRATIVE_HARNESS.md) 说明可执行命令与结构。此次升级不重写现有剧情。

## 每场写作前后的必经步骤

1. 从任务文本定位章节、场景和进度；context.py --scene 返回事件前/后状态。闲聊、可重复NPC对话用 --at 指定此前主线节点。未知时点必须查调用位置与条件，不把章末、后期成长或测试种子当默认起点。
2. 读本章完整稿及必要相邻章，相关角色完整档案；按实际经历的事件恢复状态，明确双方各自的信任、好感、警惕、敌意、依赖、隐瞒与未解矛盾。可选经历只有显式提供完成时点才重放。
3. 对照客观发生、角色所知/相信/怀疑/误解、玩家已看见、作者已定未揭露、未来计划六类信息。读相关伏笔与揭露上限；玩家的幕后视角不自动赋给任何主角。
4. 读 [对白规范](DIALOGUE_STYLE.md) 与 [纯风格样本](DIALOGUE_STYLE_SAMPLES.md)。写清本场信息、每个人的行为目的、结果、因果与情绪依据、游戏动作和对话框交接，再生成文字。
5. 修改后补充事件与知识授予对象、单向关系差异、伏笔状态；检查受影响的后续事件。来源/运行文本漂移必须报告，不静默更新正史。撤回资料保留历史但退出当前依据。
6. 重新索引，运行 narrative 审查；对七个维度逐场作编辑判断，保存具体依据。机器可阻断无来源、跨视角、未来知识等标注矛盾；不能证明所有未标注中文的含义，也不能代替文笔判断。
7. 记录完整 context、候选/已实施 draft、review，挂入 task.py；修改行数时另做 pending、staging 和存档专项。finish 检查叙事记录与来源新鲜度。仅工具维护且未改运行/章稿的任务不伪造对白审查。

权威顺序：当前用户确定方向决定变更目标；当前代码和可重复运行描述实际行为；CURRENT_STATE/发行回执描述交付；章节稿按采用状态提供策划。结构化资料是带来源的索引与事件补充，不是第二套独立正文。长期建议、未知项、已撤回设计、STYLE_ONLY样本不得升级为正史。第一章当前为0.9并保留0.5幕后，第二章0.3追加未实施；历史0.6人工节奏验收依旧独立。

## 先找到本章，再开始实现

1. 读取 [分卷分章架构与登记表](NARRATIVE_ARCHITECTURE.md) 的对应条目，定位章节稿。对第一、二章分别运行 `context.py --task "第一章剧情"`、`context.py --task "第二章剧情"`；不要用一次混合查询代替每章定位。路由只提供摘录，开发前必须实际读取本章稿全文。
2. 实现前在本章稿记录版本、目标、进入/结束状态、逐场剧情、角色与玩家各自知道什么、地图/任务/演出交接、揭露上限及验收。缺稿就先补稿；不能边写代码边临时决定主线。使用 [章节模板](#章节模板)。
3. 状态分为 `OUTLINE`（构思）、`SCRIPT_READY`（策划完整，可进入开发冻结）、`DEV_FROZEN`（开发者记录采用的稿版与执行决定）、`IMPLEMENTED`（代码及验收证据已齐）。`SCRIPT_READY` 不代表用户逐句审批；`DEV_FROZEN` 是执行记录，不是新权限申请。用户已有授权内，补齐工程细节后继续；仅改变已确定的重要方向或真的缺关键决定时再沟通。
4. 开发者把当前章节改为 `DEV_FROZEN`，写明采用版本与少量实施调整；通过 task.py 保存 checkpoint。中途改剧情同步改稿和登记表，记录原因与知识/存档影响，禁止只有代码发生变化。
5. 实现、回放、实际游玩、存档迁移验收后，更新为 `IMPLEMENTED`，登记真实入口、文件与证据。未开发章仍保持原状态，不能因第一章完成而宣称前两章都已实装。

## 章节模板

```text
章节 ID / 卷号 / 章号 / 名称：
稿件版本 / 状态 / 方向来源 / 最后更新：
开发冻结采用版本 / 决定 / task ID：（未开始时留空）
本章核心冲突、情感目标与新的体验：
进入状态 → 结束状态：（位置、人物关系、能力、任务、公开消息）
逐场：场景 ID、地点、出场人物、玩家行动、对白、可玩/演出交接、变化：
地图与任务：主要路线、支线、空间锚点、出口锁/开放依据、可返回条件：
知识表：玩家 / 男主 / 圣女 / 薇蕾娜 / 各幕后角色分别获知什么：
揭露上限 / 可种的伏笔 / 本章绝不能说明的秘密：
美术与声音：场景对应、角色连续性、关键图、立绘表情、动作、音效：
系统契约：稳定事件 ID、存档/跳过/回看、提交点、幂等与迁移：
验收：剧情回放、真实玩家路径、地图/输入/资源、旧档与新档：
待完善事项：（明确本章是否依赖它；不能把非阻塞空位做成审批）
实现及验收证据：（开发前为空）
```

新增章使用稳定的文学 ID，例如 `V01C03`；运行 `chapter` 数字、地图所属阶段和文学章号分别记录，不能假定一一对应。长期稿修改会使 harness 内容索引过期，应重建索引；可选阅读不意味着跳过版本追踪。
